## 已修复

1. **staged 恢复日志落盘后失败：**原子文件 rename 成功、目录 fsync 失败时，内存 journal
   仍是原值，但磁盘可能已有 pending 意图。失败分支现在记录 journal_dirty，后续动作／
   正常退出必须重存权威原 journal，不再假报恢复无债务。
2. **崩溃恢复后 HAL 回到原值：**曾成功应用时，即使 HAL 外部值等于原值，也先让权到
   下一游戏；pending-only、未确认写入的原值例外保留，避免误让权。
3. **旧版 PID 缺失／失效时停止证明：**仅根据精准路径/PID 发 SIGTERM 后，还必须验证
   旧 `.ctnd.lock` inode 空闲；锁忙且无可信 PID 时拒绝后续卸载，不扫描全系统 fd。
4. **新服务误停旧 daemon：**选择新包后先校对已加载 KO 身份，再停止旧版；新文件不会
   被当作正在运行的证明，也不会先停掉旧 daemon 然后因版本失配退出。
5. **Action 停止请求与空闲竞态：**已有 `.service.stop` 内容原样保留，不能自动重启并清
   掉已有请求；进入自检、暂停服务后、写前分别确认游戏空闲。测试不能代替 HAL 互斥，
   因而仍只在空闲维护窗口使用。
6. **失败自检的同 boot 兜底：**写前原子保存 `exercise.state`（boot ID、原名单、原 enable），
   成功还原才删除。同 boot 恢复记录未清时拒绝服务重启、新自检和卸载；只在确认新
   boot 后清旧记录，不重放旧内核名单。文件不是配置，不 `source/eval`。
7. **正常 Action 后卸载报错：**安全清理名单补 `action.log`，仍保留未知文件／符号链接
   拒绝及恢复债务阻止 rmmod；不是递归删除运行目录。
8. **打包身份不一致：**在已 hash 验证的同一 KO 字节上解析 ELF `.modinfo`，要求
   version、ctn_profile、ctn_build_id、完整 vermagic 与包和验证记录一致；缺失、重复、
   错误 section／身份均拒绝。不能只 bump module.prop 后带着旧 KO 打包。
9. **安装提示：**明确默认 verify 只读；默认 Action 启用且空闲时做受控实测，其他状态只读。

本轮不增加 conf、from_server、调度／频率功能或默认 CTB 管理；不改真实 COSA 库。
