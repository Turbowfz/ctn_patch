# CTNP v3.3 一加13 CTN 链路移植：实现与真机验证记录

## 本版内容

- 版本 **v3.3 / versionCode 33**；模块 ID、安装流程、安装时按内核数字版本（6.1.141 / 6.1.157）
  选择 KO 的逻辑保持不变。
- 移植一加13 官方实现（`android_kernel_modules_and_devicetree_oneplus_sm8750`
  固定提交 `d50b305f7da9e14715a25120a4ac7b1a4b8b97c3`）的完整链路：
  - 名称写入 → 厂商 `rt_info` 登记表 → 从表中选定两槽 PID/TGID（槽1 优先，槽0 避开同 PID）
  - 自有 `sched_switch` 回调按「任务指针 token + PID + TGID + 有界名称」匹配，
    命中后按官方计时语义（饱和累加、时钟倒退丢弃、窗口起点取较大值）更新原厂商
    `critical_task_running_time_ns` 等统计原语，加速阈值与引擎完全沿用原厂。
- 与官方的差异（有意修正）：
  - 官方在清空旧登记表**之前**采样，会用到上一窗口；本实现等新登记表提交后重建，
    且无候选时清空绑定，避免沿用上一局身份。
  - 改名、`rt_info` 写入、周期轮询都会触发重建（周期 100ms 兜底探针漏触发）。
  - 受控停止：`critical_task_control` 写 `stop` 后恢复厂商回调并复核，成功才解除自引用；
    失败保持自引用，`rmmod` 以 EBUSY 拒绝，可重试。
- 校验口径：本版按用户要求退回旧版 10 项静态校验水平，不新增证据门。
  内核实际使用的布局常量（tracepoint 72/funcs 64、tracepoint_func 24/prio 16、
  thread_info.cpu 0x28、task usage 64、refcount 4）以设备 BTF 核对后作为固定常量编译期断言。
- 引用计数：`get_task_struct` 为内核内联函数（无导出符号），改为按设备 BTF 的
  `task_struct.usage` 偏移内联 `refcount_inc` / `refcount_dec_and_test` + `__put_task_struct`。

## 验证结果

### 主机

- 链路核心算法：gcc + NDK clang × 无 sanitizer / ASan / UBSan，全过。
- 构建工具、更新日志（17 版契约）、打包脚本 sh+mksh、服务生命周期 sh+mksh：全过。
- 双基线构建（WSL Debian，NDK clang 17.0.2）：141、157 均通过旧版 10 项静态校验。

### 真机（PJX110 / 6.1.157-android14-11-o-g00d81d97d759）

1. **KernelSU 安装 v3.3**：安装器识别内核 6.1.157 并选中对应 KO，分步进度正常。
2. **重启后自动加载**：`version=3.3`、`patch_ready=Y`、`critical_task_control=active`，
   daemon 启动（`daemon started pid=…`），`release_verified=1`。
3. **临时 KO 探针（两轮）**：加载、写读、三个名字拒绝、单名复制、同名重复写（4ms 返回）、
   恢复原值、受控停止 `STOP_RC=0`、`rmmod` 成功，可重复加载/卸载。
4. **真实游戏链路（三角洲 com.tencent.tmgp.dfm）**：
   - daemon 从 COSA 读到配置并在 19:13:00 写入 `[GameThread RenderThread]`；
   - 节点显示 `GameThread:21132,RenderThread:24762`（两条不同真实 PID，TGID 20705），
     连续 10 次采样稳定；`rt_info` 两线程均在表内；
   - 打开 CTB（`ct_enable=1`）后继续采样 5 次，绑定与数值稳定；
   - 退游戏后 daemon 日志 `critical_task_name restored`，节点回到
     `UnityMain:-1,UnityGfxDevice:-1`；测试期开启的 CTB 已复位为 0。
5. **告警**：测试窗口（ktime 66s→214s）无新增 WARNING。开机 34–66s 有 4 条既有告警
   （`mm/slub.c new_slab`、`sched.h:1686/1691`、`core.c:3107`），发生在本模块链路之外的
   开机高压期，与本次改动无关联证据，不作“已修复”声明。

## 未验证 / 边界

- 早前“CHTB 游戏窗口告警”未做 A/B 定根因；本轮窗口未复现不等于已修复。
