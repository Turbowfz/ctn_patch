# CTNP v3.2 检测与发布记录

## 本版内容

- 版本 **v3.2 / versionCode 32**，模块 ID 保持 `ctn_patch`。
- 用户拍板放宽两道身份门：
  - 内核只按 `uname -r` 的 6.1.141 / 6.1.157 数字版本选择 KO；完整 release 名单只作记录，
    不在名单的固件在安装/自检显示「未在实测名单」注意行，不再拒绝。
  - 厂商 game_opt 模块不再比对 SHA256；安装与开机只要求文件存在且可读。
- 内核模块侧校验保留：数字前缀 gate、vermagic 自一致、BUILD_BUG_ON 布局、
  厂商符号按名字+大小+分区+模块状态（LIVE/引用）校验、动态 KCFI；
  加载 ABI 由内核 MODVERSIONS CRC 把关，不试错、不轮换 KO。
- 安装输出改为分步进度：[1/4] 自检 → [2/4] 安装（保留开关状态+权限）→
  [3/4] 当前版本更新日志 → [4/4] 完成；自检与注意行缩进两格，失败仍为 [失败]+处理。
- daemon 与 v3.1 完全相同，未改动；包内横幅、16 版简短更新日志延续既有契约。

## 验证

- 包/安装脚本回归 **76 项 × sh+mksh**；真实服务生命周期 **12 项 × sh+mksh**；
  更新日志 **18 项**（16 版契约）——全过。
- 两套 KO 以 NDK r26b clang 17.0.2 重编，静态校验（vermagic、符号 CRC、KCFI、
  结构布局、必要 ELF sections）全过。
- 未实机：v3.2 新 KO 的加载/写读/恢复与 141 实机。开发验证包（DEVELOPMENT 标记）。

## 放宽边界说明

- 数字版本相同但完整内核不同的固件：KO 能否加载由内核 MODVERSIONS CRC 决定，
  不合则 insmod 失败、服务不启动，不会写坏内核内存。
- 厂商模块字节不同：KO 加载时按符号名+大小+分区+模块状态校验，不匹配即拒绝；
  不以 insmod 试错，不强行加载。
